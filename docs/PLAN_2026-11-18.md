# План остатка после 2.9.4

Срез: `main` после релиза `v2.9.4`, аудит 17 ноября закрыт по коду. Это единственный актуальный план остатка;
внутренние планы, аудиты и журналы прошлых проходов удалены из публичного дерева. Теги 2.9.2/2.9.3 не имеют
релиза: их прогон падал на Robolectric native graphics; 2.9.4 собран с Robolectric 4.18.1.

Короткий чек-лист только открытых пунктов: [REMAINING.md](REMAINING.md).

## 1. Правила

- **Сначала инвентаризация, потом код.** Для каждого пакета сначала выписать существующие классы/потоки и только
  потом добавлять недостающее. Закрытые пакеты не переписываются.
- **Один пакет — один проверяемый результат.** Отдельная ветка/коммиты, тесты рядом с изменением, обновлённый
  статус в разделе [«Статус»](#7-статус) этого плана и в commit message.
- **`DONE` только по приёмке.** Компиляция и зелёный unit-тест не заменяют device/live-проверку. Для внешних
  сервисов и железа статусы остаются `DEVICE_PENDING` / `LIVE_PENDING` / `BLOCKED`, пока нет доказательства.
- **Данные — через план и откат.** Миграция источника, backup/restore и sync не меняют БД до подтверждения
  плана; изменения транзакционные, с журналом/идемпотентностью и тестами на повтор.
- **Никаких обещаний по памяти/скорости без измерения.** Q03 — baseline до оптимизаций и до M05.
- **Пользовательские настройки — opt-in.** Новое поведение, меняющее чтение/звук/сеть, по умолчанию выключено.
- **Не трогать юридические NOTICE** при уборке упоминаний стороннего продукта: это отдельная задача с проверкой
  лицензии, а не «поиск и замена».

### Открытые хвосты вне списка

- **L05** — модель запросов и сохранённых полок есть, экран её не использует. Это отдельный небольшой пакет:
  восстановление фильтров, умные полки, тест на повторное открытие.
- **S03** — RSS-код есть; открыт только live-гейт на реальной ленте.
- **S04** — Audiobookshelf: нужен тестовый сервер и официальный контракт; без них `LIVE_PENDING`.
- **S06 Shizuku** — `BLOCKED`: в публичном API нет install-вызова; декоративную настройку не добавляем.
- **Устройство/live** — установка поверх 2.9.2, WebView-сессии, lock screen, манга-жесты, E-ink, PDFium/TalkBack,
  реальный RSS и аудио-поверхности. Это не кодовая работа; отмечается отдельно.
- **Стабильность Robolectric native graphics** — первый прогон релизного workflow 2.9.2 на Linux упал в
  `:app:testDebugUnitTest` с JNI `Class not found: java/nio/FloatBuffer` (Coil 3 + `GraphicsMode.NATIVE`, известный
  flake). Нужен fake/in-memory `ImageLoader` или `allowHardware(false)` в тестовом окружении; production-путь не
  менять. До этого релизный прогон считать нестабильным, а не «тесты сломаны».

## 3. Волны и зависимости

Порядок отличается от старого канонического в одном месте: внешние T01/S04/T02 не блокируют локальную
безопасность данных. B02 сначала закрывает локальные поля, а серверные поля — после появления контрактов.

| Волна | Пакеты | Результат | Гейт |
|---|---|---|---|
| 0. База | 2.9.2, device/live при появлении среды | Известный baseline и чистый `main` | release + audit |
| 1. Чтение | M03 (манга → новеллы), локально Q01 | Три главы без Loading, устойчивый anchor | C-READER, device memory/rotation |
| 2. Аудио | A02 → A01 → A03 | Понятный офлайн-выбор, один command owner, богатая карточка | C-AUDIO, device audio |
| 3. Данные | MG01 → B01 → B02 (локальные поля) → B03 | Безопасная миграция и восстановление | C-DATA, DB fixtures |
| 4. Внешнее | T01 → S04 → T02 → B02 (серверные поля), S03 live | Реальные трекеры/серверы без выдуманных API | LIVE на каждом сервисе |
| 5. Язык/редактор | N02 остаток → N04 → N05 | Настройки по engine, контекст слов, управляемые длинные операции | C-UI, C-EDITOR |
| 6. Качество | M05 (после Q03 baseline), Q01 финал, Q02, Q03, Q05 | Доказанный perf/visual/docs итог | C-RELEASE, V01–V20 |

Q02 (доступность) и Q04 (приватность) выполняются **внутри** каждой волны, а не только в конце. Q01 — локальные
выделения по мере задач, финальный проход в волне 6. Q05 — последним, по фактическому HEAD.

```
M03 ───────────────→ M05
A02 → A01 → A03
MG01 → B01 → B02(local) → B03
T01 → S04 → T02 ───→ B02(server fields)
N02 → N04
N05 (после B01/N01)
Q03 baseline ──────→ M05
Q01/Q02/Q04 — сквозные; Q05 — финал
```

## 4. Пакеты

### M03 — окно онлайн-глав

**Результат:** обычная граница главы не заменяет экран на Loading; следующая/предыдущая глава уже в окне;
прогресс и трекер двигаются только по фактически видимой странице; anchor переживает поворот и смерть процесса.

**Зависит:** M01, M02, M04 (закрыты). **Где:** `ReaderViewModel.openOnline/openChapter/openAdjacentChapter`,
`MangaController`, `MangaReaderView`, `OnlinePageSource`, `EpubController`/`SingleHtmlDocument`, новый
`domain/reader/ReaderWindow.kt`, новый session-компонент в `feature/reader-manga`.

**Подпакет M03a — манга:**
1. Выписать текущий lifecycle: один `PageSource` на главу, `UiState.Loading` при `openChapter`, закрытие старого
   контроллера. Зафиксировать владельца jobs/ресурсов и точку сохранения anchor.
2. Чистая модель `ReaderWindow`: ключи `(entryId, chapterId, pageIndex)`, окно `current ± 1`, границы глав,
   `shift`, `anchorOf`, `locate`; тесты на forward/back, первый/последний слот, смену группы и missing page.
3. `SessionPageSource : PageSource` поверх 2–3 `PageSource` глав: плоский список страниц, `file/size/name`
   делегируются главе, `close()` освобождает дальние главы. Максимум 3 главы, а не «все контроллеры».
4. `ReaderContent.OnlineManga(session)` (локалный `Manga` не менять) или chapter-aware `MangaController`;
   `MangaReaderView` рисует разделитель главы, а `onPageChanged` отдаёт `(chapterId, page)`.
5. `ReaderViewModel`: открытие создаёт окно; `openAdjacentChapter` сдвигает окно без Loading; preload следующей
   главы идёт по network policy и не отмечает read/progress; при ошибке соседа — inline Retry/Skip, текущая
   страница остаётся.
6. Anchor: глава + физическая страница + внутреннее положение; при отсутствии страницы — fallback на сохранённую
   главу. Сохранять при page change, pause, process death; восстановление после поворота/перезапуска.
7. Проверки: domain-тесты окна; feature-тест с fake `PageSource`; Robolectric на границу/поворот; device-тест на
   три главы вперёд/назад, память, ошибку сети, пустую/удалённую главу, другой scanlator, offline.
8. **Стоп:** если нельзя определить владельца текущего окна или освободить дальние ресурсы — сначала исправить
   lifecycle, не «лечить» это бесконечным кэшем.

**Подпакет M03b — онлайн-новеллы:** bounded-документ текущей ±1 главы с identity bridge (глобальный chapter ID ↔
локальный section index), без склейки всей серии в один HTML. Локальный цельный EPUB не переделывать. Anchor:
chapter + offset, fallback на сохранённую главу; прогресс/трекер — по видимой главе.

**Приёмка M03:** три главы подряд без экрана Loading; назад/вперёд; поворот и process recreation; пустая/удалённая
глава/сеть/другой scanlator; память не растёт монотонно; preload не создаёт read marks.

### A02 — офлайн-объём аудио

**Результат:** пользователь выбирает «вся книга / следующие N / выбранные треки», видит объём/неизвестность,
свободное место и Wi-Fi; частичная загрузка честно показывает доступные треки; удаление выбранного сохраняет
streaming reference и позицию.

**Где:** `AudiobookDownloader`, `AudiobookStore`, `AudioPlayerViewModel`, `AudioPlayerScreen`, manifest, settings.

1. Инвентаризация: `download(book)` качает всю книгу, `state/remove/progress`; стабильные track IDs в manifest
   (index + uri) и `playableUri(track)`.
2. Модель `AudioOfflinePlan` (ALL/NEXT_N/SELECTED, набор track IDs), persisted per book; UI sheet со списком
   треков, estimated size/unknown, disk, Wi-Fi.
3. Downloader принимает план, пишет каждый трек атомарно, не дописывает байты при смене удалённой версии
   (Range/ETag/Content-Range), перезапускает только проблемный трек.
4. Partial state отдельно от «книга добавлена»: доступные/недоступные треки, удаление выбранных копий без потери
   манифеста и прогресса; offline play не ходит в сеть.
5. Тесты: частичная граница, unknown length, 200 vs 206, истёкший URL, другой ETag, cancel/no space, restart,
   воспроизведение доступного трека без HTTP. **Стоп:** источник не даёт download — честный stream-only.

### A01 — управление аудио

**Результат:** auto-rewind — настройка (`OFF / ADAPTIVE / CUSTOM`) с наследованием defaults → книга; все команды
(экран, уведомление, гарнитура, Bluetooth) идут через один service owner; таймер и скорость не сбрасываются.

1. Инвентаризация existing: `rewindAfter`, sleep timer, skip silence, history, skip intervals.
2. `AudioSettings` + миграция; OFF действительно отключает rewind, CUSTOM — секунды; отмена таймера не перематывает.
3. Проверить audio focus, звонок, отключение Bluetooth, pause/resume, speed на границе главы; убрать дублирующий
   player, если он есть.
4. Fade/end-of-chapter/resume-after-focus — только по возможностям текущего Media3; иначе не обещать.
5. Тесты: pause durations, seek while paused, speed transition, timer cancel, focus transient/permanent, headset.
   **Стоп:** два независимых playback — сначала один owner.

### A03 — богатая аудиокарточка и внешние поверхности

Разбить на отдельные подпакеты, каждый со своей приёмкой:
- **A03a metadata:** narrator/series/language/description overrides, реальная total duration/download size;
  backup/sync mapping.
- **A03b gain:** измеренный/метаданный gain без clipping, cache анализа, отключение; не «максимальная громкость».
- **A03c widget:** один service command, текущая книга/позиция, после reboot звук сам не начинается.
- **A03d Android Auto:** сначала проверить `MediaSessionService` vs `MediaLibraryService` по документации Media3;
  browse tree/auth/offline; не менять superclass без protocol tests. Без live-устройства — `DEVICE_PENDING`.
- **A03e linked editions:** ручная связь text↔audio, переход к изданию/последней позиции без обещания точной фразы.

### MG01 — миграция источника

**Результат:** preview показывает старую/новую карточку, совпадения глав с confidence, неоднозначные/пропавшие
главы и переносимые данные; до Apply ничего не меняется; повтор идемпотентен; старый офлайн доступен.

**Где:** `CatalogRepository.migrate`, `GlobalSearchViewModel`, новый migration plan UI, `TrackerManager`, `LibraryTabs`.

1. Разделить `planMigration()` и `applyMigration()`; текущий `migrate()` оставить только как внутренний apply.
2. `MigrationPlan`: source/target identity, revisions, chapter matches + confidence, ambiguity/missing, categories
   (progress/bookmarks/tabs/tracker/user metadata/downloads), что останется на старой записи.
3. Matching: точный `number+scanlator` только при валидном номере; `-1` не match key; разные группы — review;
   page position переносить только при совместимом page count/version, иначе read status + явная потеря offset.
4. UI: preview, отказ/исправление matching, выбор категорий; до Apply не менять favorite/tabs/progress.
5. Apply: проверка revision, DB-транзакция, reversible journal; файлы вне транзакции; batch — последовательность
   подтверждённых планов с partial report/pause/restart.
6. Тесты: cancel no-op, ambiguous `-1`, changed target, failure inside transaction, repeated apply, undo, old
   downloads retained. **Стоп:** мало соответствий — просить выбор в UI, не помечать всё ниже max прочитанным.

### B01 — backup/restore и импорт чужих бэкапов

1. Инвентаризация всех таблиц/полей/файлов/настроек и текущего `BackupManager.preview/restore/createTo`.
2. Manifest: версии категорий, optional-секции, counts/space/missing source/conflicts; merge vs replace только
   явным выбором.
3. Remap зависимых ID; reset/reread — семантическое событие, не «max progress»; пароли/токены по умолчанию не
   включать.
4. Streaming decode и лимиты распаковки; staging/recovery для частичных файлов; отказ до изменения БД на
   неизвестном/повреждённом формате.
5. Фикстуры стабильного и текущего форматов с версией/происхождением; неизвестный tracker adapter не ломает
   остальные записи.
6. Тесты: empty/full DB, old schema→current, repeated merge, ID collision, truncated archive, zip limits, audio
   assets/source subscriptions, rollback failure.

### B02 — field-complete sync

1. Field matrix: persisted / exported / merged / conflict rule / tombstone / legacy absence для каждого объекта.
2. Локальные поля: audio position + stable track, bookmarks+notes, user metadata/overrides, subscriptions/settings.
   Credentials не синхронизировать автоматически.
3. Unknown fields/categories старого клиента не становятся удалением; reset/rewind/reread не затираются max;
   changed-file protection.
4. Idempotent apply, tombstones, раздельные metadata/file tasks; тесты двух изолированных БД, затем реальный
   backend. **Стоп:** нет stable identity/конфликтной политики — не делать destructive merge.

### B03 — мастер и состояние sync/фоновых задач

1. State machine backend → input → probe → categories → schedule → preview → apply; без двух sync.
2. Один status summary: last success, partial, conflicts, objects/bytes/errors; частичный успех не «всё готово».
3. Гайды backup vs sync vs files, recovery по auth/network/storage/battery.
4. Тесты invalid credentials/no permission/offline/conflict/restart; реальный WebDAV — вручную, live.

### T01 — новые трекеры

1. Таблица по 5 существующим: auth/refresh/search/bind/status/score/dates/progress/reread/privacy/delete/pending.
