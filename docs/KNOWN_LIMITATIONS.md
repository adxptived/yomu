## Formats and reading

- FB2, TXT, HTML, DOCX, MOBI/AZW3 open through EPUB conversion: in the regular mode complex DOCX layout (tables, Word footnotes, headers/footers) is simplified; MOBI is PalmDOC/KF8 text only, without HUFF/CDIC compression.
- The regular text mode still reads a DOCX chapter by chapter (Headings 1 become chapters); only the page layout reads the whole document as continuous pages. Continuous scrolling across chapters in the text mode is not implemented yet.
- **The DOCX "page layout" mode approximates Word, it is not a copy:** no columns (multi-column text flows as one); floating image wrap and frames are approximate; charts, SmartArt and EMF/WMF are placeholders; equations are plain text; comments and tracked changes are not shown (the final text is visible); fonts are substituted with metrically compatible Liberation/Carlito, others with system ones. Line and page breaks can differ slightly from Word (one table row diverged on the test document compared with LibreOffice). View-only mode: selection, dictionary and notes live in the regular mode.
- DRM is not supported: MOBI with DRM is rejected with a clear error, an encrypted EPUB with `META-INF/encryption.xml` is rejected (no decryption support).
- Fixed-layout EPUB is read by the regular (reflow) engine — the `rendition:layout` property is recognized, but there is no dedicated mode yet.
- PDF reflow (2.0.6 WIP): a geometric page analysis (XY-cut) — columns are read in the correct order, page-number headers and footers are dropped, paragraphs are rebuilt from indents, gaps and headings, hyphenated words are joined. Pages without a text layer render as an image. Artistic layouts with complex image wrapping, tables inside columns and multi-column spreads can parse imprecisely.
- Read-aloud uses the system TTS engine; quality and languages depend on the device.

## Audiobooks

- **YouTube** is read through its internal player API with clients that need no JavaScript player (the approach of yt-dlp; no GPL extractor is bundled, to keep the Apache-2.0 license). YouTube changes these rules often and asks some networks (VPNs, data centres) to sign in: Settings → YouTube signs in through the app’s WebView, the player reuses those cookies and signs InnerTube with `SAPISIDHASH`, but a network YouTube blocks outright still fails. No PO token is generated: when a video needs one, even the signed-in web-client fallback can be refused, and the app shows the “sign in / bot check” message instead. Stream addresses expire after a few hours and are refreshed before they expire (a book paused overnight asks for a new one when it resumes). Age-restricted, members-only and "made for kids" videos do not play. Checked against live YouTube in November 2026 (search, playlists of 80+ videos, chapters, streams); after many requests a data-centre address gets the bot check, and then only the iOS client answers, with HLS only: streaming can still go through it, but downloading for offline listening needs a single-file stream and fails with YouTube’s message.
- **NotebookLM** has no public API for personal notebooks, and Google blocks its sign-in in embedded browsers: audio overviews are added as downloaded or shared files.
- Chapters embedded in M4B/M4A (QuickTime chapter track or Nero `chpl`) and MP3 files (ID3v2 `CHAP`) are read; other formats (Ogg, FLAC cue sheets) are not. Folders and playlists use their tracks as chapters; YouTube videos use the chapters YouTube shows (written or automatic), else their description timestamps. Chapters of videos inside a YouTube playlist are not fetched (one request per video).
- Online audiobooks (YouTube, podcasts, catalog streams) stream by default; the player’s download button saves their tracks next to the book for offline listening (YouTube in 10 MB ranges, resumable). Live streams and HLS-only videos cannot be downloaded. Audiobook folders and online audiobooks are left out of book-file sync; their progress and metadata sync like other books.
- LibriVox search matches the start of a title or an author's surname (its API has no full-text search). A YouTube playlist adds at most 500 videos. A YouTube channel link adds its newest 500 uploads, oldest first. The YouTube catalog source searches with YouTube’s own filters (long videos, all videos, playlists); its "popular" page is a search for "audiobook" ("аудиокнига" on Russian devices).
- Verified with unit tests and builds only, not on a device.

## Translation, dictionaries, OCR

- OCR and offline translation use Google ML Kit: they require Google Play Services and a one-time model download. Without GMS (e.g. an F-Droid build) these features are unavailable; online translation and dictionaries work.
- "Google" in online translation is a public endpoint without a key: limits and blocks are possible. For reliability — DeepL/LibreTranslate/LLM with your own key.
- Lemmatization is rule-based for en/ru/ja and simple suffix stripping for other languages; no morphological dictionaries. Japanese has no tokenizer (Kuromoji): a word under the finger is resolved by rule-based deinflection and the longest JMdict match.
- Book translation from the card creates a new EPUB copy from the saved book (not the editor draft) — of the whole book or, since 2.0.0, selected chapters; selected chapters can be translated right in the draft in the editor.

## Editor

- Manga: page translation (OCR → translation → typesetting, since 2.0.0) paints the original over with the block's rectangle — the bubble color, white or black; there is no clening brush for irregular bubbles and text over art. The translation font is the system one, no typeface choice; vertical Japanese text is recognized by ML Kit worse than horizontal. Included: page reorder/delete/insert, rotation, margin crop (auto and manual), brightness/contrast/gamma/grayscale, dual-page splitting, merge, recompression, cover, ComicInfo.xml.
- Find & replace in EPUB works inside text nodes: a match broken by tags (`<b>syl</b>lable`) is not found; "in markup" mode searches the source XHTML.
- Non-EPUB books are saved as EPUB, CBR/CB7/folders as CBZ. "Replace original" for linked (not copied) files needs SAF write permission; otherwise a copy is saved.
- The visual chapter editor (since 2.0.0) targets text and simple styling (paragraphs, headings, lists, quotes, links, the book's images); complex layout (tables, SVG, MathML, per-element classes and styles) is safer to edit in source XHTML. Paste is text-only. The editor has not been verified in Android WebView yet.
- Manga: no merging several chapters into a volume or splitting volumes; export is CBZ, PDF and EPUB, without an "image folder" option.
- Bulk metadata editing (since 2.0.0) changes Yomu's library data, not the OPF inside files: to get metadata into the EPUB itself, save the book through the editor.

## Catalog and extensions

- Mihon/Tachiyomi compatibility follows the public extension API (lib 1.4 and 1.6). Six extensions were verified live: 5 built-ins work, Comikey does not (chapter pages would not load). Extensions needing Mihon's internal classes will not load. Trackers — Shikimori, AniList, MyAnimeList (since 2.0.0, see [TRACKING.md](TRACKING.md)), MangaUpdates and Kitsu (since 2.0.6); Komga and other Mihon trackers are not supported.
- The catalog and global search show only the device language and English by default; other languages are selected in Catalog → Languages (the choice is saved).
- Source filters are only those the extension provides. For example, NHentai.xxx has no page-count filter (and the page count does not come in search results), and languages are separate sources ("NHentai.xxx" EN, JA, ZH, ALL).
- Extensions from repositories load via `DexClassLoader` from a private folder; this works on Android 8–15, but Google Play forbids loading executable code — a Play build needs extension repositories disabled.
- `QUERY_ALL_PACKAGES` requires justification in Google Play.
- The built-in public sources (Gutenberg, Standard Ebooks, Feedbooks, ManyBooks, Gutendex, Open Library/Internet Archive) and built-in extensions depend on the sites; a site change breaks the source until an update (extensions update from the repository with the same signing key).
- A Cloudflare check (and extension 403/503 responses) is passed manually in WebView; there is no automatic solution. Automatic retries only help with transient errors: timeouts, connection drops, 429, 5xx.
- "Download new chapters" triggers only for library titles and only from update-check results (scheduled or manual); new chapters found while opening a title are queued manually. "Download while reading" is also for library titles only. Downloads respect "Wi-Fi only": without Wi-Fi the queue waits.
- At most 2 simultaneous downloads per site — the value is fixed and not configurable (the total number of parallel downloads is configurable).
- Source state ("not responding", "responding slowly") is kept only in memory: after an app restart the hints disappear until new errors.
- Chapter reading order (reader, "Continue", "Download next", auto-download) is derived from chapter numbers and the source order. "One chapter version" and picking your group's version rely on numbers: chapters without numbers count as different, and sources that renumber chapters per volume do not merge copies from different groups. For sources with very unusual numbering the order can be wrong — the "As in source" sorting shows the list as is but does not affect reader navigation.

## App

- **The traffic counter is an estimate.** It counts the app's own traffic (catalog requests, covers, pages, downloads, extensions) by header and body sizes "on the wire"; built-in browser pages (WebView, Cloudflare checks) and system downloads are not counted, so the numbers can be lower than Android's. A network counts as metered when Android marks it as such (tethering and metered Wi-Fi count the same way).
- **The data saver** applies to a chapter when it opens: if the network changed during reading, preloading changes from the next chapter. Covers not in the cache are not shown on mobile data while "Load covers on mobile data" is off, until Wi-Fi.
- Instant lock also fires after returning from the system file picker if it was open longer than ≈1.5 s.
- The "Word search" screen (opened from "Find in Yomu" in other apps) has no back arrow — it closes with the system gesture.
- Sync (2.0.0–2.0.6): deletions of highlights, notes, bookmarks, words, tabs and online titles travel as marks. Since 2.0.6 books travel as deletions too, when file sync and the deletions setting are on: an unchanged copy is deleted with its records and the library file, a changed one is kept with a conflict on the "Sync conflicts" screen; server blobs are not deleted, image folders are not covered by deletions. Changed book files are adopted explicitly ("keep my version" / "take the other version"): re-binding progress, annotations and trackers is journaled and resumes after a crash; repeat changes (including the app writing highlights into PDFs itself) are published automatically. Legacy (`dir:`) folders migrate to stable identities by a user action, other devices follow the marker. Folder page changes do not stop the other folders: an ambiguous folder is skipped with a recorded problem, publishing/accepting a version resets positions on changed/removed pages with a report (annotations stay "dangling", the reader refuses stale jumps). Strong ETags and conditional writes are required, HTTPS recommended; the server can see the contents. Transfer is not encrypted by the app and needs space and traffic. Locally deleted books do not return on the same device; devices with older versions do not know the adoption and deletion markers — update all of them. Online-chapter progress is still "last writer wins". Real devices, WebDAV servers and cloud providers were not verified — only simulated exchanges and MockWebServer.
- PDF file highlights (2.0.0): Yomu writes Highlight/Underline/StrikeOut annotations as an incremental update at the end of the file and replaces its own update while the file ends with it; if another program changed the file afterwards, the next update is appended after its changes (the file grows). Encrypted PDFs and PDFs without write permission are not touched — highlights stay in the database only. Annotations drawn by other programs are rendered on the page but are not converted into Yomu's highlights.
- The "Continue reading" widget updates while the app process is alive and on the system schedule (every 6 hours); after a force stop the fresh one appears on the next launch.
- Restoring a backup keeps existing rows that share a primary key and is refused outright when the archive belongs to a different library (the same numeric ids would be different books): restore such a backup into an empty library. Book files, audiobook manifests and their downloaded tracks are part of a full backup.
- Updates: download resumption works when a checksum is available; the certificate is checked before the installer, but a signing-key change is not supported yet; Android additionally verifies the install.
- A release build without the `YOMU_KEYSTORE_*` variables is refused by `assembleRelease` (it must not be signed with the public debug key); use `assembleFast` for a release-like local build.
- 1.1.0 was signed with a different key than 1.0.0 (the 1.0.0 key was not kept), and the 1.2.0 APK in this repo with a new key (the 1.1.0 keystore is not in the sources): it does not install over the old version — uninstall it after a backup and restore after installing. Alternatively build 1.2.0 with your 1.1.0 keystore.
- Statistics counts time by reading sessions: a session ends after 5 minutes without actions; time in "page layout" mode counts too.
- Only arm64-v8a and x86_64 are built (no armeabi-v7a for older 32-bit devices).
