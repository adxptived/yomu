## What changed

### B03 — sync setup wizard
- `domain/sync/SyncWizard.kt`: `canAdvance` gate shared by the UI and `advance`; pure `classifySyncFailure` mapping
  auth/network/storage/battery/other from backend error text.
- `feature/settings/SyncWizardUi.kt` (new): a real stepper over all seven steps — backend, credentials, connection
  probe, categories, schedule, confirmed preview, publish on Finish. Recovery banner and card show a localized advice
  line and a retry-vs-setup action.
- `SettingsViewModel` drives the pure state machine, owns the connection check, and writes settings only after the
  preview is confirmed. `SyncSection` gains a "Set up sync" entry point. RU/EN strings added.
- Tests: `SyncWizardTest` (canAdvance, failure classification).

### N04 — glossary and opt-in text index
- `domain/glossary/Glossary.kt`: stable glossary identity by normalized name/aliases inside a book, merge/replace with
  local-id retention and alias carry-forward, export/import round trip.
- `domain/index/IndexPlan.kt`: `IndexPlan`/`IndexEstimate` on top of `LongTask`/`TaskRegistry` — cancel is never done,
  partial results are not fulltext, `searchKind` distinguishes heading search from a built index.
- Database schema **19**: `glossary_entries`, `indexed_text` + FTS4, `GlossaryDao`, `IndexedTextDao`, migration 18→19
  and exported schema JSON. `BackupCategory.GLOSSARY` participates in manifest/counts/create/restore with book-id remap.
- `FulltextIndexRepository` (estimate/rebuild/cancel/incremental/OCR attach/delete-with-book) and `GlossaryRepository`,
  Koin singletons; `fulltextIndex` setting defaults to OFF. Words screen gains a Glossary tab and an honest Index panel.
- Tests: `GlossaryIndexTest`, `IndexPlanTest`, `GlossaryRepositoryTest`, `FulltextIndexRepositoryTest`,
  `GlossaryBackupTest`, `DatabaseMigrationTest` (18→19 with FTS MATCH and cascade).

### N05 — long editor operations
- `domain/task/LongTask.kt`: `RecoveryJournal` with per-task events/outcomes, reverse-order rollback plan, cancelled and
  failed never reported as done, snapshot restore, and `publishPlan` gating.
- `feature/editor/CleaningLayer.kt`: reversible staged brush (apply/undo/redo/discard) that never writes the original.
- `EpubWorkspace`: volume grouping plus merge/split using the existing History-based undo. `EditorViewModel` persists
  the journal across drafts and stages output → validates → publishes atomically, with cancel and temp cleanup.
- `EpubEditorUi`: volume merge/split actions, staged brush controls, task progress/cancel banner. RU/EN strings added.
- Tests: `RecoveryJournalTest`, `CleaningLayerTest`, volume tests in `EpubWorkspaceTest`.

### Q01 — reader component owners
- `ReaderInputRouter` (one input channel, dispose drops queued intents), `ChapterNavigator` (reading order/window,
  snapshot/restore, cancels in-flight opens), `PageActionExecutor` (one cancellation owner + capability resolver).
- `ReaderViewModel` delegates to them without changing its public API. `onCleared` disposes all three owners.
- Tests: `ReaderInputRouterTest`, `ChapterNavigatorTest`, `PageActionExecutorTest` — cancellation, idempotent dispose,
  rotation/recreation without leaked jobs.
